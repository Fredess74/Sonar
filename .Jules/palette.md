## 2024-05-01 - Sidebar Interactive Timeline Step Elements Improved Keyboard Accessibility

**Learning:** The interactive timeline list item steps in `Sidebar.tsx` were previously `div` elements with `onClick` handlers. Because `div`s are not inherently focusable without `tabIndex=0` and lack keyboard interaction semantics, they posed an accessibility challenge for users relying on keyboards to navigate steps. Screen readers would also not announce them natively as interactive. A common fix was changing them to `<button>` which natively supports `Tab` navigation. Furthermore, using `type="button"` ensures it doesn't accidentally trigger parent forms. Combining `<button>` with Tailwind's `focus-visible:` pseudo-class (e.g. `focus-visible:ring-2 focus-visible:ring-sonar-accent`) provides robust accessibility improvements. Lastly, adding `aria-current="step"` explicitly communicates the current state to screen readers instead of purely relying on visual cues.

**Action:** Whenever building interactive list-like components (like timeline steps or list items) that serve an interactive purpose but aren't links, implement them as semantic `<button type="button">` elements with explicit layout overrides (`w-full text-left`), `aria-current` indicators when selected, and use `focus-visible` for keyboard focus styles. This pattern is essential to satisfying standard UX accessibility rules within the project.
