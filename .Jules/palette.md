## 2025-04-14 - Semantic List Items and Interactive Tab Focus
**Learning:** In the Sonar application, custom interactive elements (like the route timeline steps in Sidebar and BottomSheet) were previously rendered as `<div>` tags, which suppressed native keyboard navigation functionality and semantic significance to screen readers. Specifically, because these step items lacked explicit focus styles and `button` semantics, a keyboard-only user couldn't effectively interact with or visualize their position in the itinerary flow.
**Action:** When creating interactable lists that function as custom controls or step selectors, always use the semantic `<button type="button">` element instead of `<div>`. Ensure that elements visually denote focus state via explicitly defined utility classes like `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-sonar-accent`. Finally, properly communicate current application states to accessibility trees using `aria-current="step"`.
